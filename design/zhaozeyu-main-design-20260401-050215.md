## Problem Statement

容器内的 AI agent（Claude Code 或其他）能读写挂载的代码，但无法在宿主机上执行编译/运行等命令。当前需要手动退出容器执行命令，打断自动化流程。

现有解决方案（SSH、`docker.sock`）无法满足定制化的需求：
- SSH 不提供内置的白名单控制和审计日志
- `docker.sock` 权限控制太粗
- 需要在宿主机上统一管理（不是在容器内）

需要构建一个 server-client 系统：宿主机运行 server 接收命令，容器内 client 包装成工具供 agent 调用。

## What Makes This Cool

解决了一个**真实的工作流断点**。agent 能改代码，但要跑命令得人工介入。

这个问题的本质不是"远程执行命令"，而是**容器内外执行能力的桥接**。一旦这个桥接存在，agent 就能自动化完整的工作流（修改 → 编译 → 测试 → 修复），而不需要人类在中间循环操作。

这是一个小但关键的 infra 级基础设施——不是业务功能，但会让整个开发体验上一个台阶。

## Constraints

1. **宿主机版本问题**：大部分 C++ 开发环境都很老旧，升级会带来隐藏问题，server 端需要通用兼容（支持 CentOS 7 / glibc 2.17+）
2. **执行特性**：命令可能耗时很长（编译、测试），需要考虑超时/异步和返回内容流式处理
3. **协议灵活性**：前后端协议最好未来能支持多种，目前想到的是 HTTP，第一版跑通
4. **配置管理**：
   - **配置文件模版**：在代码仓库中（`config/config.yaml.example`），作为参考
   - **用户配置文件**：在代码外部（`~/.config/exec-server/config.yaml`），通过 `exec-server init` 生成
   - 用户需要手动修改配置文件，不通过代码管理
5. **兼容性**：Phase 1 仅支持 Claude Code，多 agent 支持推迟到 Phase 3

## Premises

1. **第一版本目标是跑通核心流程**——不追求完整功能，重点验证架构可行性
2. **技术栈选择**：
   - Server：Go 1.18+（支持泛型，便于接口定义的代码结构预留）
   - Client：优先 Go（与 server 同技术栈），备选 Python（已有请求库）
3. **部署方式**——用户在宿主机启动 server，容器内安装 client 并配置
4. **最小可用版本**——能够接收命令、执行、返回结果（包含基本输出）
5. **渐进式扩展**——第一版同步，后续加异步+SSE；代码结构预留扩展性
6. **白名单配置**：字面匹配和正则匹配分离，避免转义地狱，支持动态加载
7. **兼容性**：Phase 1 实现通用 CLI，Claude Code skill 作为集成示例（多 agent 支持推迟到 Phase 3）
8. **安全性边界**（Phase 1 必须实现）：
   - **认证**：客户端必须携带 API Token（配置文件生成随机 token，client 和 server 共享）
   - **命令注入防御**：
     - `command` 字段：禁止 shell 元字符（`|`, `&`, `;`, `$`, `` ` ``, `$()`, `<`, `>`, `||`, `&&`）
     - `args` 数组：允许合法字符（文件名可能包含 `&`, `(` 等）
   - **环境变量限制**：Phase 1 禁止自定义环境变量（`env` 字段 Phase 1 不支持）
   - **环境变量继承**：最小化继承策略（仅 PATH, HOME, USER 等必要变量，不继承 server 进程的所有环境变量）
   - **工作目录限制**：强制校验 `cwd` 必须在 `allowed_paths` 内（真实路径解析，防止 `..` 跳出；解析失败返回 400）
   - **输出大小限制**：stdout/stderr 合计最大 10MB，超出截断并在响应头标记
   - **超时限制**：Phase 1 硬编码 30 秒超时，超时调用 `cmd.Process.Kill()` 并终止进程组
   - **并发限制**：全局最大并发数 5（防止资源耗尽）
9. **审计日志**（Phase 1 简化版本）：记录基本字段（命令、参数、工作目录、token 前缀、exit_code、duration_ms、是否截断）
10. **进程清理**：启动时设置 `cmd.SysProcAttr.Setpgid = true`，超时终止时 kill 进程组（确保子进程也被清理）
11. **配置文件安全**：配置文件权限设置为 600（仅 owner 可读写），API Token 通过配置文件传递（假设宿主机已受保护）

## Approaches Considered

### Approach A: 最小可用版本（MVP）

单文件 Go HTTP server，同步阻塞执行，一次性返回结果。白名单是命令级别正则，审计记录到文件。

**优点：**
- 单个二进制文件，部署简单
- HTTP 协议通用
- 逻辑简单，1-2 天完成

**缺点：**
- 同步阻塞，长命令会卡住
- 没有预留扩展接口
- 白名单需要转义正则

**未采用：** 代码是一次性设计，后续扩展成本高

---

### Approach B: 理想架构

Go server + 异步任务队列 + HTTP/SSE 双协议。细粒度白名单，完整审计。

**优点：**
- 异步执行，实时流式输出
- 白名单细粒度控制
- 功能完整

**缺点：**
- 复杂度显著增加（任务队列、并发控制）
- 第一版需要 3-5 天

**未采用：** 功能优先于跑通，过度设计

---

### Approach C: 命名管道方案

基于 Unix FIFO 实现，零网络开销。Container 写管道，宿主机守护进程执行。

**优点：**
- 性能最好
- 不占用端口

**缺点：**
- 并发需要认真设计文件锁
- 协议非标准
- 多机器无法使用

**未采用：** 调试复杂度大于收益

---

### Approach D: 渐进式架构（推荐）

三阶段渐进式设计：

**Phase 1（第一版）：**
- API `/exec`：同步执行，一次性返回
- 内存中不保存任务状态
- 适用于短命令（编译、单测）

**Phase 2（第一个 patch，解决超时）：**
- API `/exec/async`：提交任务，返回 `{task_id: "xxx"}`
- API `/exec/status?id=xxx`：查询状态 + 结果
- Client 轮询
- 内存任务队列（LRU 淘汰）

**Phase 3（未来扩展）：**
- API `/exec/stream?id=xxx`：SSE 实时流式输出
- HTTP handler 根据 `Accept: text/event-stream` 头判断返回方式（Phase 3 实现，Phase 1 不涉及）

**代码结构预留：**
- `TaskManager` 接口（第一版不实现，Phase 2 实现）
- `Executor` 接口（支持同步和异步切换）

**白名单配置：**
- 字面匹配（`g++`）和正则匹配（`^bash\\s+-c`）分离
- 动态加载（检查配置文件修改时间）

**优点：**
- 第一版跑通核心流程
- 架构有扩展性，后续升级成本低
- 白名单配置友好（不需要转义）
- 动态加载不需要重启

**缺点：**
- 第一版没有异步（Phase 2 解决）
- 架构预留略微增加第一版工作量

**采用：** 平衡了第一版进度和未来扩展性

## Recommended Approach

采用 **Approach D（渐进式架构）**，按 Phase 1 → Phase 2 → Phase 3 顺序实现。

**Phase 1（第一版）的核心组件：**
1. **Go HTTP Server**：监听端口，接收请求
2. **Executor**：执行命令（同步）
3. **WhitelistChecker**：检查白名单（字面+正则，动态加载）
4. **Auditor**：记录审计日志
5. **Config Loader**：加载 ~/.config/exec-server/config.yaml

**Phase 2（patch）：**
1. **TaskManager 接口**：`MemoryTaskManager` 实现
2. **新增 API**：`/exec/async` 和 `/exec/status`
3. **Client 轮询逻辑**

**Phase 3（未来）：**
1. **SSE handler**：流式返回输出
2. 复用 Phase 2 的任务 ID 机制

**技术选型：**
- Server：Go 1.18+（静态编译，保证通用性）
- 配置文件：YAML（人类友好，不需要转义）
- 日志：JSONL（易于解析，机器和人类都可读）

## API 接口规范（Phase 1）

### POST /exec

**请求头：**
```
Authorization: Bearer <api_token>
Content-Type: application/json
```

**请求格式（Phase 1）：**
```json
{
    "command": "make",
    "args": ["-j4"],
    "cwd": "/home/user/project"
}
```

**字段说明：**
- `command`（必填）：可执行文件名（不含路径），使用 `exec.LookPath` 在 `$PATH` 中查找
- `args`（可选）：参数数组，默认 `[]`
- `cwd`（必填）：工作目录，必须在 `allowed_paths` 内
- `env`：Phase 1 不支持，返回 400 错误

**命令查找策略：**
- 使用 `exec.LookPath(command)` 在 `$PATH` 环境变量中查找可执行文件
- 继承最小化环境变量（仅 PATH, HOME, USER 等，不继承 server 进程的所有环境变量）
- 如果命令不在白名单内或查找失败，返回 403 Forbidden

**成功响应（200 OK）：**
```json
{
    "exit_code": 0,
    "stdout": "Build succeeded\n",
    "stderr": "",
    "duration_ms": 1234,
    "truncated": false
}
```

**错误响应：**

**401 Unauthorized**（认证失败）：
```json
{
    "error": "unauthorized",
    "message": "missing or invalid Authorization header"
}
```

**400 Bad Request**（参数错误）：
```json
{
    "error": "invalid_request",
    "message": "command is required"
}
```

**403 Forbidden**（白名单拒绝）：
```json
{
    "error": "forbidden",
    "message": "command 'rm' is not in whitelist"
}
```

**403 Forbidden**（工作目录不在允许范围）：
```json
{
    "error": "forbidden",
    "message": "cwd '/etc' is not in allowed_paths"
}
```

**408 Request Timeout**（超时）：
```json
{
    "error": "timeout",
    "message": "command exceeded 30s timeout"
}
```

**413 Payload Too Large**（输出超出限制）：
```json
{
    "exit_code": 0,
    "stdout": "Build succeeded\n...(truncated at 10MB)",
    "stderr": "...(truncated at 10MB)",
    "duration_ms": 1234,
    "truncated": true
}
```

响应头：
```
X-Output-Truncated: true
X-Output-Size-Bytes: 10485760
```

**503 Service Unavailable**（并发数已满）：
```json
{
    "error": "service_unavailable",
    "message": "maximum concurrent executions (5) reached"
}
```

**500 Internal Server Error**（系统错误）：
```json
{
    "error": "internal_server_error",
    "message": "server startup failed: listen tcp :8080: bind: address already in use"
}
```

**Server 启动错误场景：**
- 端口冲突（`listen :8080: bind: address already in use`）：返回 500 并提示更换端口或停止占用进程
- 配置文件无效：日志目录创建失败，返回明确错误并退出
- Token 无效：配置文件中 `api_token` 为空或格式错误，返回 500

**500 Internal Server Error**（执行失败）：
```json
{
    "error": "execution_failed",
    "message": "failed to start command: permission denied"
}
```

**安全约束（Phase 1 强制）：**

1. **认证**：所有请求必须携带有效 API Token（`Authorization: Bearer <token>`），无 token 或无效 token 返回 401
2. **并发限制**：全局最大并发执行数 5，超出返回 503
3. **禁止 shell 元字符**：`command` 和 `args` 中不允许出现 `|`, `&`, `;`, `$`, `` ` ``, `$()`, `<`, `>`，检测到返回 400
4. **禁止自定义环境变量**：`env` 字段 Phase 1 不支持，存在返回 400
5. **工作目录强制校验**：`cwd` 必须解析为真实路径（`filepath.EvalSymlinks`）后，在 `allowed_paths` 内
6. **输出大小限制**：stdout + stderr 合计最大 10MB，超出截断并在响应头标记 `X-Output-Truncated: true`
7. **超时限制**：硬编码 30 秒，超时调用 `cmd.Process.Kill()` 并返回 408
8. **命令格式**：必须使用 `exec.Command(command, args...)` 形式，禁止 `exec.Command("bash", "-c", cmdString)` 形式

## 配置文件示例（Phase 1）

**路径：** `~/.config/exec-server/config.yaml`

```yaml
server:
    listen: "0.0.0.0:8080"
    timeout_seconds: 30
    max_output_mb: 10
    max_concurrent: 5
    api_token: ""  # 初始化时生成随机 token

whitelist:
    # 字面匹配：完全匹配命令名，不需要转义
    literal_commands:
        - "make"
        - "cmake"
        - "g++"
        - "gcc"
        - "python3"
        - "pytest"

    # 正则匹配：需要正则特性时使用（需要转义）
    # 注意：禁止使用 bash -c 形式，会绕过参数数组的安全检查
    regex_commands:
        - "^pip\\s+install"

    # 路径限制：前缀匹配（会解析符号链接和 ..）
    allowed_paths:
        - "/home/user/projects"
        - "/tmp/build"

    # 动态加载：每 5 秒检查配置文件变化
    # 如果配置文件损坏（非法 YAML），保留旧配置并记录错误日志
    reload_interval_seconds: 5

audit:
    enabled: true
    log_file: "~/.local/share/exec-server/audit.log"  # 使用用户目录避免权限问题
    rotation_max_mb: 10
    rotation_count: 10  # 保留 10 个轮转文件
    # 日志格式：JSONL（单行 JSON）
    # Phase 1 字段：timestamp, command, args, cwd, token_prefix (前8位),
    #              exit_code, duration_ms, output_size_bytes, truncated, allowed_by
    #
    # 示例记录：
    # {
    #   "timestamp": "2026-04-01T05:02:15Z",
    #   "command": "make",
    #   "args": ["-j4"],
    #   "cwd": "/home/user/project",
    #   "token_prefix": "a1b2c3d4",
    #   "exit_code": 0,
    #   "duration_ms": 1234,
    #   "output_size_bytes": 5678,
    #   "truncated": false,
    #   "allowed_by": "literal"
    # }
```

**配置初始化命令：**
```bash
exec-server init --config ~/.config/exec-server/config.yaml
```

这会：
1. 生成默认配置文件
2. **自动生成随机 API Token**（64 字符 hex）
3. 创建日志目录 `~/.local/share/exec-server/` 并验证权限
4. 验证配置文件完整性（检查 `allowed_paths` 目录存在，`literal_commands` 不为空）

用户需要：
1. 修改 `literal_commands` 和 `allowed_paths`
2. 将生成的 `api_token` 复制到 client 配置中

## Distribution Plan

**Server 端：**
- 构建：Go 静态编译，兼容老系统
  ```bash
  # CentOS 7 兼容（glibc 2.17+）
  CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -ldflags="-s -w" -o exec-server ./cmd/server
  ```
- 发布：GitHub Releases（支持 Linux x86_64, ARM64）
- 配置：`exec-server init --config ~/.config/exec-server/config.yaml` 生成配置文件模版和随机 API Token
- 启动：`exec-server --config ~/.config/exec-server/config.yaml`
- 验证：`exec-server --verify`（检查配置文件和日志目录权限）
- 日志目录：自动创建 `~/.local/share/exec-server/`（避免权限问题）

**Client 端：**

**Go Client（优先）：**
- 构建：`go build -o exec-client ./cmd/client`
- 配置文件：`~/.config/exec-client/config.yaml`
  ```yaml
  server_url: "http://localhost:8080"
  api_token: "a1b2c3d4e5f6..."  # 从 server 配置复制（64 字符 hex）
  timeout_seconds: 35  # 客户端超时应比服务端略长，避免网络延迟导致的误判
  ```
- CLI 接口：
  ```bash
  # 同步执行（Phase 1）
  exec-client exec --command make --args "-j4" --cwd /home/user/project

  # 配置管理
  exec-client config set server_url http://localhost:8080
  exec-client config set api_token <token>
  ```

**Claude Code Skill 集成：**
- 在容器内的 Claude Code 配置目录创建 skill
- Skill 调用 `exec-client` CLI
- 配置文件路径：`~/.config/claude/skills/exec-host/`
- 示例 skill 定义：
  ```yaml
  name: exec-host
  description: Execute commands on host machine from container
  command: exec-client exec --command {{command}} --args {{args}} --cwd {{cwd}}
  ```

**CI/CD：**
- GitHub Actions 自动构建 multi-arch 二进制
- 每次提交到 main 自动发布 snapshot
- tag 触发正式 release

## Next Steps

1. **Phase 1 实现**：
   - 设计数据结构（`Command`、`Result`、`WhitelistConfig`、`AuditEntry`）

     - 验证 `Authorization: Bearer <token>` 头
     - 从配置文件读取 `api_token`
     - 使用常量时间比较防止时序攻击
   - 实现 `ConcurrencyLimiter`：
     - 使用 `sync.Semaphore` 或带缓冲 channel 控制并发数
     - 全局最大并发 5
   - 实现 `Executor` 接口：
     - 使用 `exec.CommandContext(command, args...)` 形式
     - 实现 shell 元字符检查函数（`command` 字段正则匹配 `\||\||&&|&|;|\$|`|\$\(|<|>`）
     - 实现输出大小限制（自定义 `LimitedWriter` 记录是否达到限制，在响应体和响应头标记）
     - 实现超时控制（`context.WithTimeout` + `cmd.Process.Kill()` + 终止进程组）
   - 实现 `WhitelistChecker` 接口：
     - 字面匹配和正则匹配分离
     - 工作目录校验（使用 `filepath.EvalSymlinks` 解析真实路径；解析失败返回 400）
     - 动态加载（检查文件修改时间；配置文件损坏时保留旧配置并记录错误日志）
   - 实现 `Auditor` 接口：
     - JSONL 格式日志（每行一个 JSON 对象）
     - 使用单独 goroutine 串行化写入（channel buffer）
     - 记录简化字段（token 记录前 8 位，如果不足 8 位记录全部）
